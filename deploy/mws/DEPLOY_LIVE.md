# DEPLOY_LIVE — развёртывание Genesis-Live на `anu-live-1` (фаза L5b)

Пошаговый раннбук первого реального запуска живой вселенной на
существующей VM `anu-live-1` в MWS, **в тех ограничениях, которые есть
сейчас**, без новых дисков и без новых машин.

Каждый шаг заканчивается **проверяемым критерием**. Шаг без выполненного
критерия не считается пройденным, и следующий за ним не начинается.
Шаги помечены: **[владелец]** — может выполнить только владелец аккаунта
(секреты, IAM, консоль MWS); **[оператор]** — главный агент по этому
раннбуку; **[необратимо]** — отдельно оговорено.

Артефакты этой фазы: `compose.live.yml`, `.env.live.example`,
`deploy/mws/tiers.anu-live-1.json`,
`experiments/genesis-live/config.anu-live-1.json`,
`deploy/mws/bootstrap-anu-live-1.sh`, `deploy/mws/anu-live.service`,
`deploy/mws/anu-secrets.service.d/10-before-docker.conf`.
Инфраструктурная часть (SA, ключи, сеть, firewall, реестр) — фаза L5a,
`deploy/mws/provision.sh` и `deploy/mws/RUNBOOK.md`.

## 2. Отступления от дизайна, принятые сознательно

Дизайн трека (`anu/final.md` §2) описывает четыре хоста. Есть один.
Ниже — что именно из-за этого нарушено, чем это чревато и когда снимается.
Ни одно из отступлений не отменяет инвариантов улик: единый редьюсер,
записанные входы, хэш-цепочка, аттестация каждой эпохи.

| # | Отступление | Чем чревато | Когда снимается |
|---|---|---|---|
| О-1 | **Ключ провайдера лежит на той же машине, что и улики.** Дизайн разносит шлюз когниции (`anu-cog-fast-1`) и ядро улик, чтобы компрометация одного не давала другого. Второго хоста нет: квота vCPU не даёт создать VM | Одна успешная компрометация `anu-live-1` даёт и ключ провайдера, и весь корпус улик. Остаточные меры: ключ читает только контейнер шлюза из tmpfs; раннер физически не имеет маршрута наружу (сеть `internal: true`); у шлюза нет доступа к каталогу улик | Созданием `anu-cog-fast-1` после увеличения квоты vCPU. Раннер при этом не меняется — он и сейчас ходит к шлюзу по имени сервиса |
| О-2 | **Нет выделенного диска улик.** Улики, журналы docker и аудит шлюза делят один 50 GB boot-диск | Заполнение диска бьёт одновременно по уликам, по ОС и по docker. Меры — раздел 8 | Подключением диска после освобождения квоты `nbs-pl2` (перенос каталога — обратимая операция при остановленном стеке) |
| О-3 | **Нет ops-хоста.** Нет tick-атомарной реплики, второго Observer, независимой верификации `anu lab replay`+`verify-attestation` на каждую ссылку цепочки, якорения в S3 и сверки аудита шлюза с уликами | Единственная копия улик — на этой машине. Ошибку в цепочке некому обнаружить независимо | Созданием `anu-ops-1`. Частичная компенсация доступна сразу: зеркало `chain/` на Lab (Ш10) |
| О-4 | **Нет `think-fabric`.** В дизайне это статический Caddy-allowlist между раннером и удалёнными шлюзами | Отступление без последствий: шлюз локальный, а раннер и так в сети без маршрута наружу | Вместе с О-1 |
| О-5 | **Сеть Observer'а не `internal`.** ИЗМЕРЕНО (docker 27.3.1, Lab, 2026-09-08): опубликованный порт контейнера в сети с `internal: true` с хоста недоступен (`curl` -> код 000), в обычной bridge — 200 | У контейнера Observer'а есть egress. Он не держит ключа провайдера, монтирует улики `:ro` и никогда ничего не пишет | Снимается, если понадобится, переходом на Caddy в той же сети без публикации порта |

## 3. Раскладка на диске

Всё на boot-диске, три поддерева с разными правами — это не косметика,
а граница ролей:

```
/var/lib/anu-live/
├── evidence/   улики. Раннеру rw, Observer'у ro. Внутри: genesis-live/U0001/**, chain/, anchors/
├── inbox/      записанные входы оператора: tasks.jsonl, verdicts.jsonl, physics.jsonl
│               пишет root, раннеру смонтировано ТОЛЬКО НА ЧТЕНИЕ
└── gateway/    аудит и состояние бюджета шлюза. Это НЕ улики; раннер сюда не имеет доступа
/opt/anu-live/  compose.live.yml, .env, tiers.json, anu-secrets.sh, (Caddyfile)
/run/anu/secrets/  tmpfs, три файла секретов, 0400, uid 1000
```

Каталог `inbox/` вынесен из корня улик намеренно (дизайн кладёт его
внутрь): раннер не должен иметь права записи туда, откуда он читает
собственные записанные входы.

`verdicts.jsonl` создаётся, но по умолчанию **не подключён**: внешнюю
работу оценивает модель-грейдер через тот же шлюз (`ANU_LIVE_GRADER_MODEL`),
и это выбор в пользу одного egress, одного бюджета и одного аудита.
Файл существует, чтобы переключение было одной строкой: добавить
`--verdict-inbox /inbox/verdicts.jsonl` в команду раннера. Учтите, что
источник вердиктов **перекрывает** грейдера (в CLI inbox выигрывает), а
`evaluatorId` входит в идентичность эпохи — переключение меняет
идентичность последующих эпох, см. раздел 7.

## Ш1. Привязать внешний адрес **[владелец]** *(обратимо)*

Пока `anu-live-1-ip` не привязан к VM, к машине нет ни одного сетевого
пути: подсеть приватная, а `ssh-from-lab` разрешает вход только с
185.233.3.14 — но и он бесполезен без публичного адреса.

```bash
# Проверить текущее состояние (чтение, безопасно)
mws vpc external-address get "vpc/projects/project-vxgxs2/externalAddresses/anu-live-1-ip" -f json
mws vpc one-to-one-nat list --network anu-live -f json
```

Привязка выполняется в консоли MWS либо командой `vpc one-to-one-nat
create` — **точная форма команды не подтверждена реальным запуском**
(в `provision.sh` этот шаг намеренно только печатается, а не выполняется:
изменение сетевых интерфейсов работающей VM способно отсоединить её
boot-диск или сеть).

**Критерий:** `mws vpc one-to-one-nat list --network anu-live -f json`
показывает связку 178.236.27.13 → 10.77.0.10, и с Lab отвечает порт:
`nc -z -w5 178.236.27.13 22 && echo reachable`.

## Ш2. Доступ к машине по SSH **[владелец]**

**ОТКРЫТЫЙ ВОПРОС, который надо закрыть до начала работ:** неизвестно,
есть ли на `anu-live-1` хоть один SSH-ключ. VM создана в обход
провижининга, cloud-init не применялся, а IAM `authorized-key
vm-anu-live-1` — это ключ сервисного аккаунта для CLI `mws`, **не** ключ
входа по SSH. Если ключа нет, единственный путь — консоль MWS
(serial/VNC): добавить публичный ключ оператора в `~/.ssh/authorized_keys`
пользователя с sudo. Менять `vm update --network-interfaces` на живой
машине не следует (риск отсоединения диска/сети).

**Критерий:** с Lab отрабатывает
`ssh -o BatchMode=yes <user>@178.236.27.13 'id && lsblk && df -h /'`
и печатает один диск на 50 GB.

## Ш3. Привести голую Ubuntu в рабочее состояние **[оператор]**

Скопировать и запустить `bootstrap-anu-live-1.sh` — это ровно те
действия, которые описывает `cloud-init.yaml`, выполненные вручную и
идемпотентно, **минус** раздел про отдельный диск улик (его нет):

```bash
scp deploy/mws/bootstrap-anu-live-1.sh <user>@178.236.27.13:/tmp/
ssh <user>@178.236.27.13 'sudo bash /tmp/bootstrap-anu-live-1.sh'
```

Скрипт: проверяет свободное место (< 20 GB — отказ), заводит uid 1000
(или использует занятый), ставит Docker Engine + compose plugin, создаёт
дерево `/var/lib/anu-live` и пустые файлы входов, создаёт `/opt/anu-live`,
создаёт `/run/anu` **и объявляет его в `/etc/tmpfiles.d/anu-live.conf`**.
Последнее обязательно: `/run` — tmpfs, после перезагрузки каталог исчезает,
а у `anu-secrets.service` стоит `ConditionPathExists=/run/anu` — без
правила tmpfiles сервис после ребута молча не запустится и стек останется
без секретов.

**Критерий:**
```bash
ssh <user>@178.236.27.13 'docker compose version && \
  test -d /var/lib/anu-live/evidence && test -f /var/lib/anu-live/inbox/tasks.jsonl && \
  test -d /run/anu && stat -c "%a %U" /run/anu'
```
печатает версию compose и `700 root`.

## Ш4. Секреты и IAM **[владелец]** *(значения секретов — необратимо в смысле «агент их не видит и не должен видеть»)*

Ни одно значение секрета не проходит через агента, через репозиторий и
через `.env`. Владелец лично:

1. Создаёт версии трёх секретов в MWS Secret Manager (контейнеры уже
   существуют, значений в них нет):
   - `anu-live-provider-key` — ключ к MWS GPT (SA-ключ `anu-live-inference`);
   - `anu-live-gateway-token` — общий Bearer раннера и шлюза, не короче
     32 символов token68;
   - `anu-live-observer-token` — Bearer читателя улик.
   Точный формат ввода данных версии — **НЕПРОВЕРЕННЫЙ ФАКТ**
   (`docs/GENESIS_LIVE.md` §8): подтвердить при первом запуске и вписать
   результат в `RUNBOOK.md` §3 и в `anu-secrets.sh`.
2. Назначает IAM role bindings (CLI это не умеет — только консоль/REST),
   по чеклисту `RUNBOOK.md` §2: SA `anu-live` — чтение секретов `anu-live-*`
   и pull из реестра `anu`.
3. Устанавливает на VM профиль `mws` (0600, root) — без него
   `anu-secrets.service` не прочитает ничего.

**Критерий (выполняет владелец на VM):**
```bash
mws secretmanager secret-version get-data --name anu-live-gateway-token -f json >/dev/null && echo readable
```
без ошибки авторизации — и НЕ показывая содержимое в общем канале.

## Ш5. Секреты в tmpfs **[оператор]**

```bash
scp deploy/mws/anu-secrets.sh <user>@178.236.27.13:/tmp/
ssh <user>@178.236.27.13 'sudo install -m 0750 -o root -g root /tmp/anu-secrets.sh /opt/anu-live/anu-secrets.sh'
scp deploy/mws/anu-secrets.service deploy/mws/anu-live.service <user>@178.236.27.13:/tmp/
scp deploy/mws/anu-secrets.service.d/10-before-docker.conf <user>@178.236.27.13:/tmp/
ssh <user>@178.236.27.13 'sudo install -m 0644 /tmp/anu-secrets.service /tmp/anu-live.service /etc/systemd/system/ && \
  sudo install -d /etc/systemd/system/anu-secrets.service.d && \
  sudo install -m 0644 /tmp/10-before-docker.conf /etc/systemd/system/anu-secrets.service.d/ && \
  sudo systemctl daemon-reload && sudo systemctl enable --now anu-secrets.service'
```

Drop-in `10-before-docker.conf` обязателен и нетривиален. Контейнеры
объявлены с `restart: unless-stopped`, поэтому после перезагрузки их
поднимает сам `dockerd`, не дожидаясь ни `anu-live.service`, ни
`anu-secrets.service`. А `/run` — tmpfs: секретов там после ребута нет.
Drop-in ставит чтение секретов **перед** запуском `dockerd`. Цикла нет:
`anu-secrets.service` зависит только от `network-online.target`.

Если формат ответа Secret Manager окажется не тем, что предполагает
`anu-secrets.sh` (поле `data` в base64), скрипт упадёт с внятной ошибкой —
поправить одну строку разбора и записать факт в `RUNBOOK.md` §3.

**Критерий:**
```bash
ssh <user>@178.236.27.13 'systemctl is-active anu-secrets.service && \
  ls -l /run/anu/secrets/ && stat -c "%a %u %n" /run/anu/secrets/*'
```
— три файла, режим `400`, владелец `1000`. **Содержимое не печатать.**

## Ш6. Образ движка **[оператор]**

Реестр принимает PUSH только с 185.233.3.14, поэтому сборка и push идут
**с Lab**, а VM только тянет.

```bash
# на Lab, в /root/anu-wt/genesis-live
docker login registry.mwsapis.ru        # учётные данные вводит владелец
bash scripts/live/build-push.sh
```

**НЕПРОВЕРЕННЫЙ ФАКТ — сверить при первом push.** `build-push.sh` строит
путь `registry.mwsapis.ru/anu/agent-native-universe-lab`, а по косвенному
свидетельству (`SELLERY_INFRA_STATE.md` §6) полный путь включает имя
проекта: `registry.mwsapis.ru/project-vxgxs2/anu/agent-native-universe-lab`.
Если push отказывает — задать `MWS_REGISTRY_HOST` или поправить
`IMAGE_PATH` в скрипте, и привести к тому же виду `ANU_LIVE_IMAGE` в
`.env`. Значение `ANU_LIVE_IMAGE` **обязано быть пиннутым тегом**
`live-<short-sha>`: `compose.live.yml` не имеет значения по умолчанию и
падает без него намеренно.

Скопировать стек на VM:

```bash
scp compose.live.yml .env.live.example deploy/mws/tiers.anu-live-1.json <user>@178.236.27.13:/tmp/
ssh <user>@178.236.27.13 'sudo install -m 0640 -o root -g docker /tmp/compose.live.yml /opt/anu-live/compose.live.yml && \
  sudo install -m 0644 /tmp/tiers.anu-live-1.json /opt/anu-live/tiers.json && \
  sudo cp /tmp/.env.live.example /opt/anu-live/.env && sudo chmod 0640 /opt/anu-live/.env'
# затем вписать в /opt/anu-live/.env реальный ANU_LIVE_IMAGE
ssh <user>@178.236.27.13 'cd /opt/anu-live && sudo docker compose -f compose.live.yml config -q && sudo docker compose -f compose.live.yml pull'
```

**Критерий:** `docker images` на VM показывает образ с пиннутым тегом, а
`docker compose config -q` завершается без вывода.

## Ш7. Эпоха 0 — вручную, один раз **[оператор]** *(создаёт цепочку; удаление улик необратимо)*

Первую эпоху запускаем **не сервисом**, а одной командой с `--epochs 1` —
чтобы увидеть её целиком и измерить реальный размер, прежде чем отдавать
вселенную в автономный режим.

```bash
ssh <user>@178.236.27.13 'cd /opt/anu-live && \
  sudo docker compose -f compose.live.yml up -d lab-llm-gateway-live lab-observer-live && \
  sudo docker compose -f compose.live.yml run --rm --no-deps lab-runner-live \
    node dist/lab/runner.js live --data-dir /data \
      --config /app/experiments/genesis-live/config.anu-live-1.json \
      --universe-id U0001 --tiers /config/tiers.json \
      --task-inbox /inbox/tasks.jsonl --physics-inbox /inbox/physics.jsonl \
      --outage-ticks 3 --min-free-bytes 8589934592 --epochs 1'
```

Команда печатает одну строку JSON на эпоху: `{"status":"epoch","epoch":0,
"runId":…,"ticks":250,"events":…,"commitment":"sha256:…"}` и затем
`{"status":"stopped"}`.

**Критерии (все три):**
```bash
# 1. Ссылка цепочки эпохи 0 существует
sudo ls /var/lib/anu-live/evidence/genesis-live/U0001/chain/0.json
# 2. Аттестация эпохи существует и её commitment совпадает с напечатанным
sudo cat /var/lib/anu-live/evidence/genesis-live/U0001/run-*/attestations/final.json
# 3. Агенты действительно консультировались
sudo grep -c '"type":"cognition.recorded"' /var/lib/anu-live/evidence/genesis-live/U0001/run-*/events.jsonl
```
Потолок — 4000 (16 агентов x 250 тиков), и ровно столько получилось в
измеренном прогоне. Заметно меньше — законный, но требующий объяснения
исход: часть агентов была отсечена по бедности (нет консультации вовсе)
либо провайдер отвечал отказом (запись есть, но `provider` в ней —
`unavailable`). Разделить одно от другого:
```bash
sudo grep -o '"provider":"[a-z-]*"' /var/lib/anu-live/evidence/genesis-live/U0001/run-*/events.jsonl | sort | uniq -c
```

**И сразу же — измерить диск** (это вход в Ш8):
```bash
sudo du -sb /var/lib/anu-live/evidence /var/lib/anu-live/gateway
sudo df -B1 --output=avail /var/lib/anu-live
```

## Ш8. Автономный режим **[оператор]**

```bash
ssh <user>@178.236.27.13 'sudo systemctl enable --now anu-live.service && systemctl status anu-live.service --no-pager'
```

`anu-live.service` перед подъёмом проверяет: три секрета на месте и
являются обычными файлами (иначе docker создал бы на месте отсутствующего
файла каталог, и отказ был бы поздним и невнятным), дерево улик и файлы
входов на месте, `compose config -q` проходит. Остановка — `stop -t 600`,
а не `down`: раннер должен успеть доиграть текущий тик и записать
чекпойнт.

**Критерий:** `systemctl is-active anu-live.service` = `active`, и
`docker compose ps` показывает три сервиса, из них шлюз и Observer —
`healthy`.

## Ш9. Проверка живости **[оператор]**

Внешнего входа на Observer нет и не планируется: он опубликован только на
петле VM. С Lab — SSH-туннель по уже существующему образцу
`deploy/mws/lab/anu-live-tunnel@.service`:

```bash
# на Lab: /etc/anu-live-tunnel/observer.env (0600)
#   ANU_LIVE_TUNNEL_HOST=178.236.27.13
#   ANU_LIVE_TUNNEL_USER=<user>
#   ANU_LIVE_TUNNEL_REMOTE_PORT=3000
#   ANU_LIVE_TUNNEL_LOCAL_PORT=13000
systemctl enable --now anu-live-tunnel@observer
curl -s -H "Authorization: Bearer <observer-token>" http://127.0.0.1:13000/api/live | python3 -m json.tool
```

**Критерий «вселенная живёт»** — все четыре, подряд:
1. `head.lastTick` в `/api/live` растёт между двумя вызовами;
2. `cognitionHealth.consulted > cognitionHealth.unavailable + cognitionHealth.starved`;
3. `chain` содержит записи, и их число не уменьшается;
4. `docker logs` раннера не содержит `"status":"paused"` — либо содержит с
   явной причиной (`provider_outage` / `low_disk`), и тогда это не «живёт»,
   а «на паузе по названной причине». Пауза не оставляет следа в уликах —
   это операционный факт, и искать его надо в логе, а не в цепочке.

Эпоха 0 этой самой физики прогнана целиком на Lab, с настоящим шлюзом и

| Величина | Измерено |

| Тиков в эпохе / агентов | 250 / 16 |
| Событий | 23 545 |

Рычаг оператора — записанная физика (`/var/lib/anu-live/inbox/physics.jsonl`): управляющий
контур меняет **цены**, и только их, никогда не роли и не задания.

## 6. Что значит «эта вселенная меньше канонической»

`experiments/genesis-live/config.anu-live-1.json` отличается от
канонической физики ровно пятью значениями (`agents`, `ticks`,
`live.epochTicks`, `initialResources.llmTokens`, `seed`), и каждое —
следствие машины, а не вкуса. Последняя строка таблицы — то, что
осознанно НЕ менялось, но требует объяснения. Полное обоснование каждого числа — в `.env.live.example`,
раздел 7; инвариант «остальное байт в байт каноническое» проверяется
тестом `test/lab-live-deployment-anu-live-1.test.mjs`.

| Значение | Канон | Здесь | Коротко почему |
|---|---|---|---|
| `agents` | 32 | 16 | одна консультация на агента на тик — число агентов и есть нагрузка на шлюз и на 4 vCPU |
| `ticks` / `live.epochTicks` | 500 | 250 | граница эпохи — единственная точка реплея, аттестации и компактизации; реплей однопоточный |
| `initialResources.llmTokens` | 200 000 | 400 000 | при измеренных 1580 единицах на консультацию канонический запас сделал бы первой стеной токен мышления, а не заработок |
| `seed` | `genesis-live-u0001` | `genesis-live-anu-live-1-u0001` | чтобы вселенную с другой физикой нельзя было спутать с канонической |
| `checkpointEvery` | 25 | 25 | **не менялось** — названо явно: падение стоит до 25 x 16 = 400 реальных консультаций |

Всё остальное — цены действий, поток задач, окна архивации, цены ярусов,
истощение, казна — каноническое. Инварианты сохранены полностью: единый
редьюсер, записанные входы, хэш-цепочка, аттестация каждой эпохи.

## 7. Личность цепочки: что нельзя менять на ходу

В манифест каждой эпохи и, значит, в её `runId` входят: физика вселенной
(`configHash`), идентичность когниции (`cognitionId` — ярусы, их модели и
цены, хэш идентичности шлюза, бюджет содержимого) и идентичность грейдера
(`evaluatorId`). Практический вывод для эксплуатации:

- **`ANU_LIVE_IMAGE` пиннится поимённо.** Плавающий тег означает, что код
  и физика, породившие цепочку, невосстановимы.
- Смена модели в `tiers.json`, смена `ANU_LIVE_GRADER_MODEL` или смена
  `ANU_LIVE_LLM_UPSTREAM` — это смена технического лечения. Цепочка
  останется валидной, но следующие эпохи будут иметь другую идентичность.
  Делать это можно только осознанно и записывать факт.
- **Инвариант**: `pricePpm` каждого яруса в `tiers.json` обязан совпадать
  с `live.tiers.<ярус>.pricePpm` в конфиге вселенной. По первому
  предсказывается платёжеспособность агента, по второму редьюсер списывает
  токены; расхождение делает экономику мышления враньём. Проверяется тестом.
- `ANU_LIVE_GATEWAY_MAX_IN_FLIGHT` не меньше суммы `concurrency` ярусов
  (4+2+1) плюс грейдер. Тоже проверяется тестом.

## 8. Диск: порог и поведение при заполнении

Это главный операционный риск отступления О-2.

**Порог.** `ANU_LIVE_MIN_FREE_BYTES=8589934592` (8 GiB). Встроенный в
движок порог по умолчанию — 20 GiB — рассчитан на выделенный диск улик
300 GB; на общем 50-гигабайтном boot-диске он сработал бы почти сразу.
8 GiB оставляют место на: чекпойнт текущего тика, полный реплей и
аттестацию текущей эпохи (они пишут `summary.json` и `attestations/`
**после** того, как страж мог сработать), журналы docker (3 x 10 MB на
сервис), аудит шлюза (до ~512 MB с ротацией) — и запас, чтобы оператор
успел выгрузить улики.

**Поведение.** Страж диска проверяет `statfs` корня улик перед каждой
эпохой и на каждом тике. При падении ниже порога вселенная **встаёт на
паузу на границе тика**: текущий тик доигрывается, чекпойнт ложится на
диск, и дальше не коммитится ничего — ни `task.expired`, ни
`tick.completed`. Пауза не оставляет следа в уликах; в логе раннера
появляется `{"status":"paused","reason":"low_disk"}`. Восстановление —
проба каждые `probeIntervalMs`; как только места стало больше, эпоха
продолжается с той же границы и завершается **байт в байт** так же, как
если бы паузы не было.

**Ёмкость.** По измерению из раздела 5: ~18.2 MB на эпоху. При ~10 GB на
ОС, docker и образы и 8 GiB резерва под улики остаётся ~31 GB, то есть
порядка **1700 эпох (~425 000 тиков)**. Даже при трёхкратно больших
ответах модели — порядка 570 эпох. Мир ограничен по состоянию
(архивация + компактизация на границе), поэтому размер эпохи не растёт
со временем — это тоже видно из прогона.

**Что делать при приближении к порогу** (ручная, обратимая процедура —
автоматической выгрузки нет, см. раздел 9):
1. убедиться, что эпоха завершена (есть `summary.json`, `attestations/final.json`
   и ссылка `chain/<k>.json`);
2. скопировать каталог эпохи на Lab и проверить копию;
3. удалить с VM **только** каталоги полностью завершённых, скопированных
   и подтверждённых эпох. **`chain/` и `anchors/` не удалять никогда** —
   это индекс всей жизни вселенной; и не удалять эпоху, которая является
   родителем текущей.

## 10. Остановка, пауза, аварийная остановка

| Что нужно | Как | Что происходит с вселенной |
|---|---|---|
| Штатная остановка | `systemctl stop anu-live.service` | SIGTERM -> пауза на границе тика, чекпойнт на диске, контейнеры остановлены. Возобновление продолжает ту же эпоху |
| Остановить только мышление | `mws iam api-key update ".../apiKeys/anu-live-inference" --active=false` **[владелец]** | шлюз перестаёт давать ответы; через `--outage-ticks` подряд идущих тиков без ответа страж ставит вселенную на паузу на границе тика |
| Пауза по диску | автоматически | см. раздел 8 |
| После `kill -9` / OOM | автоматически | `restart: unless-stopped` поднимает раннер; `--recover-stale-lease true` перехватывает аренду писателя, которую процесс **доказательно** признал протухшей (сменился `boot_id` хоста либо pid держит процесс с другим временем старта). Условие безопасности: против одного каталога улик никогда не запускается второй раннер |
| Полная остановка стека | `systemctl disable --now anu-live.service` | контейнеры остановлены; улики, тома и сети на месте |

Ротация секретов, восстановление из резервной копии и учёт ключей —
`deploy/mws/RUNBOOK.md` §5–6 и `deploy/mws/KEYS.md`.
